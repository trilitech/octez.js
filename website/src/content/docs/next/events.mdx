# Contract Events

## Introduction
Contract events is a way for contracts to deliver event-like information to third-party (off-chain) applications. It can be emitted by using the EMIT instruction in Michelson.

For more details and examples of how the EMIT instruction works, refer to [this article](https://octez.tezos.com/docs/active/event.html).

## Getting contract events in octez.js
You can get the events in a contract through the `eventSchema` field of the `ContractAbstraction`.

### Example
#### Usage
```typescript
const Tezos = new TezosToolkit(RPC_URL);
const contractAbstraction = Tezos.contract.at('KT1...');
console.log(contractAbstraction.eventSchema);
```

If the contract has events this might log something similar to:

```json
[
  {
    "tag": "%tag1",
    "type": {
      "prim": "int"
    }
  },
  {
    "tag": "%tag2",
    "type": {
      "prim": "int"
    }
  },
  {
    "tag": "%tag3",
    "type": {
      "prim": "string"
    }
  }
]
```


## Subscribing to Events in octez.js
octez.js provides a simple way for users to subscribe to certain events on the blockchain via the `PollingSubscribeProvider`.

### Example
#### Usage
```typescript
const Tezos = new TezosToolkit(RPC_URL);

Tezos.setStreamProvider(
  Tezos.getFactory(PollingSubscribeProvider)({
    shouldObservableSubscriptionRetry: true,
    pollingIntervalMilliseconds: 1500
  })
);

try {
  const sub = Tezos.stream.subscribeEvent({
    tag: 'tagName',
    address: 'KT1_CONTRACT_ADDRESS',
    excludeFailedOperations: true
  });

  sub.on('data', console.log);

} catch (e) {
  console.log(e);
}
```


- `tag` is the tag string that was defined in the smart contract with the EMIT instruction
- `address` is the address of the smart contract that was called
- `excludeFailedOperations`: In rare cases, events from failed operations can be received by the subscriber. You can use this field to filter out these events (if you pass `true` to this field, only events from successful operations will be received)

The `setStreamProvider` call is optional: it configures polling, as described in
[Choosing and configuring the stream provider](#choosing-and-configuring-the-stream-provider).

:::info
If you would like to subscribe to **_any_** event that goes through, you can call `subscribeEvent()` as is without any parameters
:::

## Subscribing to the chain

`Tezos.stream` provides subscriptions to new heads, blocks, operations and contract events. Event
subscriptions are described above; the others work the same way:

```js
const sub = Tezos.stream.subscribeOperation({ destination: 'KT1...' });
sub.on('data', (op) => console.log(op.hash));
sub.on('error', (err) => console.error(err));
// later
sub.close();
```

### Choosing and configuring the stream provider

By default this is a `PollingSubscribeProvider` that polls through the toolkit's read provider:
the node set with `setRpcProvider`, unless you installed another read provider with
`setReadProvider`. To poll a specific node, pass its URL:

```js
Tezos.setStreamProvider('https://rpc.example.org');
```

To change how polling behaves, create the provider with a configuration:

```js
import { PollingSubscribeProvider } from '@tezos-x/octez.js';

Tezos.setStreamProvider(
  Tezos.getFactory(PollingSubscribeProvider)({
    pollingIntervalMilliseconds: 1000,
    shouldObservableSubscriptionRetry: true,
  })
);
```

- `pollingIntervalMilliseconds`: if you don't set it, the provider uses one third of the
  protocol's `minimal_block_delay`, with a minimum of 700 ms. If the protocol constants can't be
  read, it polls every 5 s.
- `shouldObservableSubscriptionRetry`: `false` by default, so the first error is emitted on
  `'error'` and the subscription stops. When it's `true`, every error is still emitted on
  `'error'`, then the subscription waits one polling interval and starts polling again.
  `observableSubscriptionRetryFunction` replaces that retry strategy with an RxJS operator of your
  own.

### Sharing between subscriptions

All subscriptions created from the same provider share a single polling loop:

- A new subscription doesn't replay data the shared stream has already delivered. A subscriber
  that joins an active stream only receives heads, blocks or operations that appear after it
  joined.
- Polling stops when the last subscription is closed. The next subscription starts a new polling
  loop.

Close subscriptions you no longer need, so polling doesn't keep running in the background.

To learn how the default provider polls the node, see
[Architecture: The TezosToolkit](/docs/next/arch_tezos_toolkit#how-polling-works).
